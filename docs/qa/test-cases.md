# 테스트 케이스

기능을 만들기 전에 설계한 TC입니다. 기능이 완성되면 실제 결과를 채우고, 자동화한 TC는 `tests/e2e/`의 테스트 이름에 같은 ID를 붙입니다.

- **유형**: 정상 / 경계 / 예외 / 보안
- **우선순위**: P1(핵심 흐름이 멈춤) · P2(기능 일부 오류) · P3(불편)
- **자동화**: E2E = Playwright로 자동화(`npm run test:e2e`), Unit = 단위 테스트(`npm run test:unit`), 수동 = 사람이 확인, 평가 = `run-eval`로 수치 측정
- **결과**: Pass / Fail / Blocked / 미실행

## 모의면접

면접관이 질문 → 내 답 → 꼬리질문(최대 2개) → 질문별 피드백 순서로 진행합니다. 답변 초안을 만든 질문으로만 면접합니다.
"모르겠어요"·너무 짧은 답·꼬리질문 개수 제한은 AI 없이 규칙으로 처리해 결과가 매번 같고(테스트 가능) 비용이 들지 않습니다.
