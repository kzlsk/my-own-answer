## CLAUDE.md · 스킬 활용

- 1일차: `CLAUDE.md`에 서비스 흐름, 범위 밖 기능, API 키 규칙, 안정성 목록, 지표, QA 규칙을 정리해 매 작업의 기준으로 사용
- 1일차: 프로젝트 전용 스킬 5개를 만듦

| 스킬 | 만든 이유 | 효과 (작업하며 채움) |
| --- | --- | --- |
| `make-test-data` | 가상 데이터에 실제 개인정보가 섞이지 않게, 까다로운 경우가 빠지지 않게 | |
| `run-eval` | v1·v2를 매번 같은 세트, 같은 형식으로 평가하려고. 채점은 사람이 하도록 못 박음 | |
| `log-prompt` | 프롬프트 변경 이유와 수치를 빠짐없이 남기려고 | |
| `write-tc` | 기능 구현 전에 정상·경계·예외·보안 케이스를 먼저 설계하려고 | |
| `e2e-test` | TC와 자동화 테스트를 ID로 연결하고, 테스트를 억지로 통과시키지 않게 | |

## AI 실수와 수정 사례

| 날짜 | AI가 한 실수 | 어떻게 발견했나 | 어떻게 고쳤나 |
| --- | --- | --- | --- |
| 1일차 | (서비스 AI) answer-v1이 맞는 경험이 없는 질문에 없는 학습 이력·QA 경험을 지어냄 (12문장) | 문장 단위 채점 (`data/results/2026-10-29-answer-v1`) | answer-v2에서 근거를 경험 답변·이력서로 제한하고, 없는 경험은 인정 후 가까운 경험으로 연결하게 함 |
| 1일차 | (서비스 AI) 마스킹 토큰 `[이름]`을 답변에 그대로 씀 ("저는 [이름]입니다") | 채점 중 발견, BUG-001 | answer-v2에 인사·이름 소개·가림 토큰 금지 추가. 화면 단계에서도 후처리 검토 |

## 설계 판단과 맞바꾼 것

| 판단 | 맞바꾼 것 | 이유 |
| --- | --- | --- |
| RAG 대신 근거 자료를 프롬프트에 통째로 넣음 | 대량 질문 은행 검색 | 자료가 작아 검색 단계가 오히려 실패 지점이 됨 |
| Notion API 대신 Markdown 복사 | 자동 업로드 | 사용자마다 토큰 설정이 필요하고 5일 범위를 넘음 |
| 배포 사이트는 데모 모드 | 배포 사이트에서 실제 생성 | 내 API 크레딧을 다른 사람이 쓰지 않게 하기 위해 |
| 답변 평가는 조합마다 질문 하나를 고정(`fixed-questions.json`) | 조합마다 여러 질문 평가 | v1·v2가 같은 질문에 답해야 공정하게 비교되고, 30건 × 1문항이어야 사람이 문장 단위로 채점할 수 있음 |
| 이력서의 `## 경험 답변` 섹션은 모델에게 이력서로 보내지 않고 "사용자가 경험 질문에 답한 내용"으로 따로 다룸 | 이력서 원문 그대로 사용 | v2의 "경험 먼저 묻기" 효과를 재려면 이력서와 사용자 답변을 구분해야 함 |
| `--limit`으로 일부만 돌려도 이력서·공고가 섞이도록 조합 순서를 설계 | 이력서 순서대로 실행 | 기준선 5건이 한 이력서에 몰리지 않게 (첫 5건: 직무 일치 1, 불일치 4) |
| 채점은 Claude가 1차 라벨(근거 위치·판단 이유를 note에 기록), 내가 검토해 확정 | 처음 계획: 전부 직접 채점 / 대안: LLM 자동 채점 | 자동 채점만 하면 AI가 AI 출력을 평가해 지표를 믿기 어렵고, 전부 직접 하면 문장 77개가 오래 걸림. 판단 근거를 남겨 검토 가능하게 하고 확정은 사람이 함 |
