# log-prompt — 프롬프트 · AI 활용 기록

제출물인 `프롬프트.md`와 발표의 "AI 활용 과정" 장을 위한 기록을 빠짐없이 남긴다.

## 1. 서비스 프롬프트를 새 버전으로 만들 때

1. 기존 파일을 **수정하지 않는다.** `prompts/<대상>-v1.md`를 복사해 `prompts/<대상>-v2.md`를 만든다.
2. 새 파일 맨 위에 HTML 주석으로 변경 요약을 남긴다:
   `<!-- v2: 바꾼 점 한 줄 / 이유 한 줄 / 근거: data/results/<폴더> -->`
3. `프롬프트.md`의 A 섹션 해당 표에 행을 추가한다. "바꾼 이유"는 **v1에서 실제로 관찰한 문제**로 쓴다 (예: "30건 중 12건에서 이력서에 없는 프로젝트를 지어냄").
4. 결과 칸은 평가 전이면 비워 두고, `run-eval` 집계 후 채운다.

## 2. 개발 중 주요 요청을 남길 때

`프롬프트.md`의 B 섹션, 해당 일차 아래에 한 줄씩:

`- <무엇을 요청했나> → <결과 한 줄> (커밋: <해시 앞 7자리>)`

긴 대화 전체가 아니라 **방향을 바꾼 요청**만 남긴다.

## 3. AI 실수를 잡아 고쳤을 때

`docs/ai-log.md`의 "AI 실수와 수정 사례" 표에 행을 추가한다:

| 날짜 | AI가 한 실수 | 어떻게 발견했나 | 어떻게 고쳤나 |

- "발견"에는 구체적인 근거를 쓴다: 실패한 TC ID, 빌드 에러 메시지, 콘솔 로그, 채점 결과.
- 관련 버그가 있으면 `docs/qa/bugs.md`의 BUG ID를 함께 적는다.

## 4. 설계 판단을 내렸을 때

`docs/ai-log.md`의 "설계 판단과 맞바꾼 것" 표에 추가한다: 판단 / 맞바꾼 것 / 이유.

## 규칙

- 수치는 `data/results/`의 실제 값만 쓴다. 추측한 수치를 쓰지 않는다.
- API 키, 실제 개인정보는 기록에 넣지 않는다.
