# make-test-data — 테스트 데이터 만들기

## 가상 이력서 (`data/resumes/`)

- 파일명: `r01-frontend.md`, `r02-backend.md`, `r03-qa.md`, `r04-marketing.md`, `r05-pm.md`
- **가상 인물만** 쓴다. 실존 인물, 사용자 본인의 실제 이력, 실제 회사 내부 정보는 넣지 않는다.
- 마스킹 테스트를 위해 가짜 개인정보를 일부러 넣는다. 형식을 섞는다:
  - 이름: 흔하지 않은 가상 이름
  - 전화: `010-0000-0000`처럼 0으로 채우거나 `010 1234 5678`, `+82-10-…` 등 형식을 다양하게 (실제 번호처럼 보이는 임의 숫자 금지)
  - 이메일: `@example.com` 도메인만
- 까다로운 경우를 섞는다: 경력이 거의 없는 이력서 1개, 개인정보가 여러 번 나오는 이력서 1개.
- 파일 끝에 `## 경험 답변` 섹션을 둔다. 답변 초안 평가 때 "사용자가 경험 질문에 답한 내용"으로 쓰인다. 이력서에 있는 경험만 3~5개, 구체적인 상황·행동·결과로 쓴다.

```markdown
# r03-qa (가상 인물)

이름: 하은솔
연락처: 010 0000 1234 / haeunsol@example.com

## 경력
...

## 프로젝트
...

## 경험 답변
- [모바일 앱 결제 QA] 상황: ... / 내가 한 일: ... / 결과: ...
```

## 채용공고 (`data/postings/`)

- 파일명: `p01-<직무>.md` ~ `p06-<직무>.md`
- 공개된 공고 본문만 쓴다. 파일 맨 위에 출처를 적는다:
  `<!-- 출처: <URL> / 수집일: YYYY-MM-DD -->`
- 회사 로고, 담당자 연락처, 지원 링크는 지운다.
- 까다로운 경우를 섞는다: 아주 긴 공고 1개, 영문 공고 1개.

## 끝나면

`data/README.md`의 목표 개수와 실제 개수를 비교해 알려 준다. 이력서 5 × 공고 6 = 30건 조합이 되는지 확인한다.
