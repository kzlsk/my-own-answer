## 사례 1: 출결 대시보드 렌더링 개선

2023.02 - 2023.05 | 스텝노트 출결 관리 화면 | React, react-window, React Profiler

**Problem**
- 학생 300명 이상인 학원에서 출결 표 첫 화면이 뜨는 데 평균 4.8초
- 출석 체크박스를 누르면 0.5초 이상 늦게 반영된다는 원장님 문의가 월 12건

**Process & Solution**
- React Profiler로 측정 → 체크박스 하나를 바꿔도 표 전체 행이 다시 그려지는 것 확인
- 행 컴포넌트를 `memo`로 분리하고, 출결 상태를 행 단위로 구독하도록 상태 구조 변경
- 화면에 보이는 행만 그리도록 react-window 가상 스크롤 적용
- 백엔드와 협의해 한 번에 전체 명단을 받던 API를 50명 단위 페이지네이션으로 변경

| 항목 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 첫 화면 표시 | 4.8초 | 1.6초 |
| 체크 반영 지연 | 약 520ms | 약 40ms |
| 관련 문의 (월) | 12건 | 2건 |

**Impact**
- 대형 학원 고객 3곳의 해지 검토 철회
- 같은 방식을 수납 내역 표에도 적용

## 사례 2: 디자인 시스템 구축

2024.06 - 2024.10 | 오름가계 웹앱 | Storybook, Tailwind CSS, Figma

**Problem**
- 화면마다 버튼 모양이 달라 비슷한 버튼이 코드에 14종 존재
- 새 화면을 만들 때마다 디자이너와 색상·간격을 다시 맞추느라 시간 소요

**Process & Solution**
- 디자이너 1명과 색상·간격·글자 크기 토큰을 먼저 정의
- 버튼, 입력창, 모달 등 공통 컴포넌트 22개를 Storybook에 정리
- 컴포넌트마다 접근성 체크(키보드 이동, 포커스 표시) 항목을 문서에 포함

**Impact**
- 신규 화면 개발 기간 평균 5일 → 3일
- 버튼 변형 14종 → 4종으로 통합

## 트러블슈팅

**문제 1. Next.js 전환 후 hydration 경고**
- Problem: 거래 내역 날짜가 서버와 브라우저에서 다르게 그려져 콘솔 경고와 깜빡임 발생
- Solution: 서버 시간대(UTC)와 사용자 시간대(KST) 차이가 원인 → 날짜 표시 부분만 클라이언트 컴포넌트로 분리
- Impact: 경고 0건, 날짜가 하루 밀려 보이던 문의 해소

**문제 2. 결제 수단 등록 폼 이중 제출**
- Problem: 느린 네트워크에서 등록 버튼을 두 번 누르면 같은 카드가 2개 저장
- Solution: 제출 중 버튼 잠금 + 요청마다 고유 키를 보내도록 백엔드와 협의
- Impact: 중복 등록 0건, 같은 패턴을 다른 폼 5개에 적용
