## 사례 2: 업데이트 전 기기 호환성 테스트

2022.03 - 2023.02 | 픽셀포레스트 모바일 RPG | 실기기 14종, Firebase Crashlytics

**Problem**
- 업데이트마다 일부 저사양 기기에서 실행 직후 꺼진다는 리뷰 발생

**Process & Solution**
- 사용자 비율 상위 기기로 Android 9종, iOS 5종 매트릭스 구성
- Crashlytics 로그와 실기기 재현 → 램 3GB 이하 기기에서 고화질 텍스처 로딩 중 메모리 부족 확인
- 저사양 기기 자동 그래픽 옵션 하향을 기획·개발팀에 제안

**Impact**
- 업데이트 직후 크래시율 1.8% → 0.4%
- 매트릭스를 업데이트 체크리스트로 정착

## 테스트 자동화: 뱅킹 앱 회귀 스모크

2024.01 - 2024.05 | 모아뱅크 Android 앱 | Appium (Java), TestNG, GitHub Actions

- 배포 전마다 손으로 돌리던 스모크 45개 중 반복 빈도 높은 30개 자동화
- 매일 밤 GitHub Actions에서 실행, 실패 시 스크린샷과 로그를 Slack으로 전송
- 수동 3시간 → 자동 25분

**트러블슈팅**
- 문제 1. 테스트 계정 잔액 소진: 이체 테스트를 반복하면 잔액이 바닥나 실패 → 테스트 시작 전 테스트 서버 API로 잔액을 고정 금액으로 맞추는 단계 추가
- 문제 2. 일회용 인증번호 입력: 문자 인증이 매번 달라 자동화 불가 → 테스트 서버에 한해 고정 인증번호를 쓰도록 개발팀과 협의
- 문제 3. 화면 요소를 못 찾는 실패: 요소 ID가 없는 화면이 많아 좌표·문구로 찾다가 자주 실패 → 개발팀에 접근성 ID 추가 요청, 주요 화면 12개 반영
