## 프로젝트

### 좌석 중복 판매 해결 | 2021.02 ~ 2021.04
- 인기 공연 예매 오픈 시 동시 접속 약 4,000명, 같은 좌석이 공연 1회에 3~5건 중복 판매
- Redis 분산 락으로 좌석 단위 선점 + DB 유니크 제약
- nGrinder로 동시 5,000명 부하 테스트
- ✅ 이후 공연 40회 연속 중복 판매 0건, 좌석 선점 p95 1.9초 → 0.4초

트러블슈팅
- 문제: 외부 결제사 응답 지연
  - 해결: 결제사 한 곳이 10초 이상 응답하지 않아 스레드가 모두 대기 → Resilience4j 서킷 브레이커 + 3초 타임아웃, 실패 건 SQS 재처리 → 장애 중에도 다른 API 정상
- 문제: 정산 내역 N+1 쿼리
  - 해결: 100건 조회에 쿼리 101번, 응답 2.3초 → fetch join + batch size → 0.3초
